# Native Android implementation status

Based on the revised Chinga PRD in `docs/Chinga_UCC_PRD_v2_Clean.pdf`. This is an implementation checklist, not a claim that planned services are deployed.

## Available in the prototype

- Native child home, message input, exact sample results, an honest unavailable state for other inputs, and screenshot selection and preview without upload.
- Parent signup with a fixed demo code (`123456`), locally persisted parent/child link, expiring single-use demo family code, and a minimal on-device alert generated by the high-risk sample. These are not real authentication, SMS, secure pairing, notifications or cross-device sync.
- Incident draft and editable preview held in memory only; the prototype does not submit a report.
- Support guidance and a dialler link for 116, with a clear statement that no call is made until the user confirms it.
- Guardian demonstration, privacy explanation, and on-device protection category preferences. They do not control network traffic.
- Internal APK build profile and EAS Update configuration are linked to the Expo project. Signed Chinga 1.3.0 / Android build 4 completed successfully; real-device installation and workflow tests are still required.
- A first-run role screen now routes parents to demo signup and children to pairing or the child home. Sign-in and privacy screens state exactly which backend capabilities are unavailable.

## Required before claiming the full non-AI product works

1. Implement authenticated accounts, guardian verification, expiring single-use pairing and role boundaries with a real API and persistent storage.
2. Implement confidential report submission and review, privacy notices, consent, safeguarding workflows, deletion and audited access. Obtain appropriate expert review before using real child data.
3. Build minimal event delivery and guardian notifications with safeguards against exposing private conversations. Add device check-ins with an honest unknown/offline state.
4. Implement Android link handling and a separately consented VpnService/domain filtering pipeline, including allowlisted support services, opt-out, VPN conflict handling, visibility limits and real-device tests. Device-owner controls require legitimate enrollment and are a separate future track.
5. Add supported screenshot sharing and secure upload; image selection currently stays on the phone. Add accessibility, localisation, age-appropriate content and support for unreliable connections.
6. Implement backend integrations and role-restricted UCC analytics, sanitised exports and audit logging. SMS, Telegram and formal referrals require service setup and explicit approval.
7. Configure EAS Update and produce a signed APK, then test installation, upgrades, permissions, privacy, back navigation and accessibility on real Android devices. Native changes require a new compatible APK.

AI inference, classification, OCR, voice and model evaluation are separate work. A UI placeholder must never be represented as a working safety check, automatic referral or device protection.
